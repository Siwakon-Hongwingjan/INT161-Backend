1. Web Application และ HTTP

1.1 HTTP คืออะไร

HTTP (HyperText Transfer Protocol) คือโปรโตคอลที่ client กับ server ใช้สื่อสารกันบน World Wide Web client ส่ง HTTP Request แล้วได้ HTTP Response กลับมา client มักเป็น browser แต่เป็นโปรแกรมหรืออุปกรณ์ใดก็ได้ ส่วน server มักเป็นเครื่องบน cloud

1.2 HTTP Methods

Methodใช้ทำอะไรตัวอย่างเสริม
GETดึงข้อมูล/subjects, /subjects/{id}Safe และ Idempotent
POSTสร้าง resource ใหม่ (มี body)/subjectsไม่ Idempotent: ยิงซ้ำสร้างซ้ำ
PUTแก้ไขข้อมูลที่มีอยู่ (มี body)/subjects/{id}Idempotent: ยิงซ้ำผลเท่าเดิม
DELETEลบ resource/subjects/{id}Idempotent
เสริม

PATCH แก้เฉพาะบาง field ส่วน PUT แทนที่ทั้ง resource · Safe คือไม่เปลี่ยนสถานะบน server · Idempotent คือเรียกกี่ครั้งผลสุดท้ายก็เท่ากับเรียกครั้งเดียว

1.3 HTTP Status Code

Status code บอกผลลัพธ์ตั้งแต่บรรทัดแรกของ Response แบ่งตามเลขหลักแรก

3xxRedirect301 Moved · 304 Not Modified
4xxความผิดพลาดฝั่ง client400 401 403 404 409 412
5xxความผิดพลาดฝั่ง server500 Internal Server Error · 503 Service Unavailable

รายละเอียดของรหัส 4xx/5xx ดูในบท Error Handling

2. Node.js และ HTTP Module

2.1 Node.js คืออะไร

Node.js ไม่ใช่ภาษาโปรแกรม แต่เป็น runtime ที่รัน JavaScript บนเซิร์ฟเวอร์ ฟรี open source ทำงานบน Windows, Mac, Linux ข้อดีหลักคือใช้ภาษาเดียว (JavaScript) ทั้ง front-end และ back-end

2.2 Compile vs Interpret vs Hybrid

2.3 Architecture: Single Thread + Event Loop

Node.js รัน JavaScript ใน thread เดียว แต่รองรับ request จำนวนมากด้วยการทำงานแบบ asynchronous / non-blocking ผ่าน async/await

เสริม

Blocking คือฟังก์ชันที่หยุดรอจนเสร็จ เช่น fs.readFileSync ถ้าใช้ใน server จะทำให้ request อื่นค้างทั้งหมด ควรใช้ await fs.readFile แทน · Node.js เหมาะกับงาน I/O หนัก (API, chat) แต่ไม่เหมาะกับงานคำนวณหนักที่ใช้ CPU นาน

2.4 Core Modules ที่ควรรู้

fs ไฟล์http server/clientpath พาธไฟล์os ระบบปฏิบัติการevents event
util ยูทิลิตีstream สตรีมcrypto เข้ารหัสurl parse URLquerystring query

2.6 HTTP Module: 4 คลาสหลัก

คลาสบทบาทสมาชิกสำคัญ

http.IncomingMessageข้อมูล request ที่เข้ามา (เป็น ReadableStream)method, url, headers
http.ServerResponseสร้างและส่ง responsewriteHead(), setHeader(), write(), end()

import * as http from 'node:http';
const listener = (request, response) => {
  const { url, method } = request;
  response.writeHead(200, { 'Content-Type': 'text/plain' });
  response.end(`You made a ${method} request to ${url}`);
};
http.createServer(listener).listen(3000);

2.7 อ่านข้อมูลจาก Request

const urlObj = new URL(request.url, `http://${request.headers.host}`);
urlObj.searchParams.get('name');       // ค่าเดียว

จากสไลด์ (Week 4)

การรับ body แบบไม่มี framework: ฟัง event 'data' ต่อ chunk เข้าด้วยกัน พอ 'end' จึง parse ซึ่งยุ่งยากมาก นี่คือเหตุผลที่ต้องมี Express (บท 4)

เสริม (สไลด์มีหัวข้อแต่ไม่ลงรายละเอียด)

Bun คือ JavaScript runtime อีกตัว ใช้ engine JavaScriptCore (Node.js ใช้ V8) รวม runtime, package manager, bundler และ test runner ไว้ในตัว เร็วกว่าในหลายงาน และรัน TypeScript ได้โดยตรง ขณะที่ Node.js มี ecosystem และความเสถียรมากกว่า โค้ดส่วนใหญ่ใช้ร่วมกันได้เพราะรองรับ API node:*

3. RESTful API

REST = REpresentational State Transfer สร้างโดย Roy Fielding เป็น สถาปัตยกรรม สำหรับ web service ฝั่ง server ให้เข้าถึง resource ฝั่ง client เข้าถึงและแก้ไข resource แต่ละตัวมี URI เป็นตัวระบุ และถูกส่งในรูป representation เช่น JSON, XML, text

3.1 หลักการและข้อจำกัด 6 ข้อ

เสริม: ทำไม Stateless สำคัญ

เมื่อ server ไม่เก็บ state เราเพิ่มจำนวน server แล้วให้ load balancer กระจาย request ไปเครื่องไหนก็ได้ ระบบ scale ง่าย นี่คือเหตุผลที่ต้องมี JWT ในบทหลังๆ เพื่อให้ client แนบ identity มากับทุก request

3.2 Uniform Interface: 4 เสาหลัก

เสาความหมาย
Resource IdentificationURI ระบุ resource ไม่ใช่การกระทำ เช่น /api/v1/users
Manipulation via Representationsแลกเปลี่ยนสถานะด้วยรูปแบบมาตรฐาน (JSON)
Self-Descriptive Messagesใช้ HTTP method และ header มาตรฐาน เช่น Content-Type: application/json
HATEOASResponse แนบ hypermedia link นำทาง client ไปยัง action ถัดไป

3.4 Layered System

ประโยชน์: (1) Scalability เพิ่ม shared cache หรือ load balancer โดย client ไม่ต้องแก้ (2) Separation of Concerns แยกการ parse HTTP ออกจาก business logic และ DB (3) Security

โครงสร้างโปรเจกต์แบบไม่ใช้ framework: server.js (เปิด server) · router.js (จับคู่ route) · services/ (business logic) · repositories/ (เข้าถึงข้อมูล)

Week 4 · Express.js

4. Express Framework

Express เป็น web framework ของ Node.js ที่ minimalist, unopinionated, fast ให้ชั้น routing และ middleware ครอบ HTTP server ของ Node.js ใช้เป็นส่วน Back-end ของ MEAN/MERN stack (MongoDB, Express, Angular/React, Node.js) Unopinionated หมายถึงเราจัดโครงสร้างแอปเองได้อิสระ

4.1 Raw Node.js vs Express

import express from 'express';
const app = express();
app.use(express.json());                      // middleware อ่าน JSON body
app.put('/api/subjects/:id', (req, res) => {
  const { filter, page, size } = req.query;   // ?page=2
  const id = req.params.id;                    // :id
  const subject = req.body;                    // body
  res.json({ ...subject, id });
});
app.listen(3000);

ติดตั้งด้วย npm install express (ระบุเวอร์ชันได้ด้วย @version)

4.2 Request และ Response

ตัวช่วยดึงอะไรตัวอย่าง URL
req.paramsตัวแปรใน path/subjects/5 → params.id = "5"
req.queryquery string/subjects?page=2&limit=10
req.bodybody ที่ parse แล้ว (ต้องมี middleware)JSON ที่ client ส่งมา
จุดที่มักออกสอบ

res.status(201) ไม่ได้ส่ง response มันคืน object res กลับมาเพื่อต่อ chain กับ .json() / .send() เช่น res.status(201).json(subject) ส่วน res.json() เดี่ยวๆ ใช้ status 200

4.3 Routing

Routing คือการกำหนดว่าแอปตอบ request อย่างไร ตาม URL + HTTP method

router.METHOD(PATH, HANDLER);
router.get('/api/user/:id', (req, res) => { ... });

Path เป็น string หรือ regex ได้ และมี parameter (:id) ได้ ใช้ express.Router() แยก route เป็นไฟล์ แล้วผูกกับแอปด้วย app.use('/products', productRouter)

4.4 Middleware

Middleware คือฟังก์ชันที่รับ (req, res, next) ทำงานคั่นกลางก่อนถึง route เช่น log, parse body, authentication, validation, CORS ถ้าเรียก next() จะส่งต่อให้ตัวถัดไป ถ้าเรียก res.send()/res.json() จะจบ response ทันที

5. เชื่อมต่อ Database ด้วย mysql2

5.1 ขั้นตอนเชื่อมต่อ

import * as mysql from 'mysql2/promise';
export const pool = mysql.createPool({ host:'localhost', user:'root', password:'***', database:'sampledb' });

const [rows, fields] = await pool.query('SELECT * FROM subjects WHERE credit = ?', [3]);

ผลลัพธ์ของ query เป็น array [rows, fields] ใช้ destructuring ดึง rows ออกมา สำหรับ INSERT/UPDATE/DELETE ค่าแรกเป็น object ที่มี affectedRows และ insertId

5.2 Connection vs Pool

Connection

การเชื่อมต่อ 1 ช่องทางไปยัง DBMS สร้างและปิดทุกครั้งที่ใช้ ช้าและสิ้นเปลือง

Pool

ตัวจัดการกลุ่ม connection ที่เปิดไว้แล้ว ยืมใช้แล้วคืน เหมาะกับ server ที่มี request จำนวนมาก

Library รองรับ 2 แบบ: Callback API ((err, results, fields) => {}) และ Promise API (async/await) ซึ่งอ่านง่ายกว่าและเป็นแบบที่ใช้ในวิชา เมื่อจบสคริปต์ทดสอบให้เรียก await pool.end()

5.3 Prepared Statement และ SQL Injection

ใช้ ? เป็นตัวแทนค่า แล้วส่งค่าจริงเป็น array แยกต่างหาก driver จะ escape ค่าให้ปลอดภัย ป้องกัน SQL Injection

เสริม

SQL Injection อยู่ใน OWASP Top 10 มาตลอด ผู้โจมตีใส่ SQL เข้าไปใน input เพื่ออ่าน แก้ หรือลบข้อมูล ชื่อตารางและชื่อคอลัมน์ใส่ ? ไม่ได้ ถ้าต้องรับจาก user ให้เทียบกับ whitelist ก่อน

Week 8 · Exception Handling

6. Error / Exception Handling

6.1 Error คืออะไรและทำไมสำคัญ

Exception/Error คือเหตุการณ์ที่ขัดจังหวะการทำงานปกติของโปรแกรม ถ้า throw แล้วไม่มีใคร catch Node.js จะ terminate process ทำให้ server ล่มทั้งตัว Error เป็น object ที่ห่อสภาวะผิดปกติไว้

ทำไมต้องจัดการ

  • กัน app crash / downtime
  • ข้อความที่ผู้ใช้เข้าใจ
  • ไม่รั่ว stack trace หรือข้อมูลลับ
  • ช่วย debug, monitor, alert

ชนิดของ Error

  • Programming Error: bug, logic ผิด (TypeError)
  • Operational Error: network timeout, DB down, ไม่พบไฟล์
  • Expected vs Unexpected: expected ต้องจัดการอย่างสุภาพ

6.2 Error Propagation

เมื่อเกิด error ในฟังก์ชัน จะถูก catch ตรงนั้น หรือ ส่งต่อขึ้นไปตาม call stack จนมีคน catch ถ้าไม่มีเลยก็ขึ้นไปถึง global scope แล้วโปรแกรมจบ

code / errnoรหัส system error ของ Node เช่น "EACCES", "ENOENT"
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = true;           // error ที่เราคาดไว้
    Error.captureStackTrace(this, this.constructor);
  }
}
throw new AppError('Subject not found', 404);

Custom error class ช่วยจัดหมวดและแนบ context (เช่น status code) เพื่อให้ตอบ client และบันทึก log ได้ตรงประเด็น

6.4 Error Handling ใน Express

เมื่อเรียก next(err) Express จะ ข้าม middleware/route ปกติทั้งหมด และกระโดดไปหา error-handling middleware

// ต้องประกาศ "หลังสุด" หลัง routes และ middleware ทั้งหมด
app.use((err, req, res, next) => {
  const status = err.status || err.statusCode || 500;
  res.status(status).json({
    error: err.code,
    statusCode: status,
    message: err.message,
    path: req.originalUrl,
    timestamp: new Date().toLocaleString()
  });
});
จุดที่มักออกสอบ

Error-handling middleware มี 4 พารามิเตอร์ (err, req, res, next) ส่วน middleware ปกติมี 3 · ถ้าไม่ได้เขียน handler Express จะส่งหน้า HTML error เริ่มต้น (มี stack trace เมื่ออยู่ใน dev mode)

เสริม: async handler

ใน Express 4 ถ้า async route ถูก reject ต้อง try/catch แล้ว next(err) เอง (หรือใช้ wrapper) ไม่งั้น error จะไม่ไปถึง handler · Express 5 จับ rejected promise ให้อัตโนมัติ · ใน production ไม่ควรส่ง err.stack ให้ client ส่วน error ที่ไม่คาดคิดให้ตอบ 500 ข้อความทั่วไปแล้วเก็บรายละเอียดไว้ใน log

7. Pagination และ DTO

7.1 ทำไมต้อง Pagination

การส่ง record ทั้งหมดกลับไปทำให้ response ใหญ่ เพิ่มงานของ DB หน่วยความจำ และ network Pagination ทำให้ client ได้ response ขนาดที่คาดเดาได้

7.2 พารามิเตอร์และสูตร Offset

ตัวอย่าง GET /api/products?page=2&limit=20 โดย page = หน้าที่ขอ · limit = จำนวน record ต่อหน้า · offset = จำนวน record ที่ต้องข้าม (คำนวณเอง)

สูตร

OFFSET = (page − 1) × limit

pagelimitoffsetrecord ที่ได้
11001-10
2101011-20

9108081-90

7.3 Flow การทำงาน

SELECT * FROM products ORDER BY productCode LIMIT ? OFFSET ?;   -- ข้อมูลหน้านั้น
SELECT COUNT(*) AS total FROM products;                       -- ใช้คำนวณ totalPages
เสริม

ควรมี ORDER BY เสมอเมื่อ paginate ถ้าไม่เรียงลำดับ MySQL ไม่รับประกันว่าลำดับ record จะเหมือนเดิมทุกครั้ง หน้าถัดไปอาจได้ record ซ้ำหรือตกหล่น

7.4 รูปแบบ JSON Response

{
  "success": true,
  "data": [ ... ],
  "pagination": {
    "page": 2, "limit": 20, "totalItems": 138,
    "totalPages": 7,        // Math.ceil(138 / 20)
    "hasNextPage": true,   // page * limit < totalItems
    "hasPreviousPage": true // page > 1
  }
}

7.5 Best Practice

  • ตรวจว่า page ≥ 1: Math.max(parseInt(page), 1)
  • กำหนด limit สูงสุด เช่น 100: Math.min(parseInt(size), 100)
  • ใช้ prepared statement
  • สร้าง index ให้คอลัมน์ที่ filter และ sort
  • หน้าลึกมากๆ ให้พิจารณา cursor pagination
เสริม: OFFSET vs Cursor

OFFSET ลึกๆ ช้า เพราะ DB ต้องอ่านแล้วทิ้ง record ก่อนหน้าทั้งหมด (OFFSET 100000 = อ่าน 100000 แถวทิ้ง) Cursor pagination ใช้ WHERE id > :lastId ORDER BY id LIMIT n ใช้ index ได้ตรงๆ จึงเร็วคงที่ แต่กระโดดไปหน้าที่ N ไม่ได้

จุดที่ต้องระวังในโค้ดสไลด์

Middleware ในสไลด์คำนวณ offset = (page - 1) * pageSize โดยใช้ pageSize ที่ยังเป็น string และยังไม่ถูกจำกัดที่ 100 แทนที่จะใช้ limit ที่ผ่าน Math.min แล้ว ถ้าส่ง limit=500 จะได้ offset ผิด ควรใช้ (page - 1) * limit

7.6 DTO: Data Transfer Object

DTO คือ object ที่กำหนด รูปร่างข้อมูลที่แลกเปลี่ยนระหว่างชั้น/ระหว่าง API กับ client แยก "สัญญา API" ออกจากโมเดลฐานข้อมูล

ประโยชน์

  • ไม่เผลอเปิดเผย field ที่ละเอียดอ่อน
  • Response สม่ำเสมอ
  • validate และเขียน doc ง่ายขึ้น
  • ลดการผูก DB กับ client (coupling)

3 สิ่งที่ต้องแยกให้ออก

  • Entity: ข้อมูลที่เก็บใน DB
  • Request DTO: ข้อมูลที่ client ส่งเข้ามา
  • Response DTO: ข้อมูลที่ API ส่งออก

7.7 Mapper: แปลง Entity เป็น DTO

export default class ProductMapper {
  static toSummaryDTO(e) {                 // ใช้กับรายการ
    return { id: e.productCode, name: e.productName, scale: e.productScale, retailPrice: e.MSRP };
  }
  static toDetailDTO(e) {                  // ใช้กับรายละเอียด
    const { MSRP, buyPrice, ...data } = e;
    return { ...data, retailPrice: MSRP, price: buyPrice };
  }
}

Route เลือกชนิด DTO ผ่าน query ?view=summary|full (list ใช้ summary เป็นค่าเริ่มต้น, รายตัวใช้ full)

จุดที่ต้องระวังในโค้ดสไลด์

getObject(id, viewType) ใน Product Service เรียก mapper.map(await repo.findOne(id)) โดยไม่ส่ง viewType ไปด้วย ทำให้ได้ DTO แบบ detail เสมอ ควรส่งเป็น mapper.map(entity, viewType)

ทดสอบตัวเอง

Stateless หมายถึงอะไร

ทุก request ต้องมีข้อมูลที่จำเป็นครบในตัวเอง server ไม่เก็บ context ของ request ก่อนหน้า client เป็นผู้เก็บ session state

ต่างกันอย่างไรระหว่าง 401 และ 403

401 คือยังไม่ผ่านการยืนยันตัวตน 403 คือยืนยันแล้วแต่ไม่มีสิทธิ์เข้าถึง resource

ทำไม res.status(404) อย่างเดียวถึงไม่ส่ง response

มันแค่ตั้ง status code แล้วคืน object res ต้องต่อด้วย .json(), .send() หรือ .end() จึงจะส่ง

หน้าที่ของ Service Layer และสิ่งที่ห้ามมีคืออะไร

เก็บ business logic, validation, การคำนวณ และประสานงานหลาย repository ห้ามมีรายละเอียด HTTP (req/res) หรือโค้ด DB ตรงๆ

เขียน offset ของ page 5, limit 20

(5 − 1) × 20 = 80 ดึง record ลำดับที่ 81-100

ทำไมไม่ควรส่ง Entity กลับ client ตรงๆ

อาจเปิดเผย field ที่ละเอียดอ่อน เช่น password_hash และทำให้ API ผูกกับโครงสร้าง DB ใช้ DTO กำหนดรูปร่างข้อมูลที่ส่งออกอย่างชัดเจน

Error-handling middleware ต่างจาก middleware ปกติอย่างไร และต้องวางที่ไหน

มี 4 พารามิเตอร์ (err, req, res, next) และต้องประกาศท้ายสุดหลัง route และ middleware อื่นทั้งหมด

Prepared statement ป้องกัน SQL Injection ได้อย่างไร

แยกคำสั่ง SQL กับค่าออกจากกัน ค่าที่ user ส่งมาถูกมองเป็นข้อมูล ไม่ถูกตีความเป็นส่วนหนึ่งของคำสั่ง
